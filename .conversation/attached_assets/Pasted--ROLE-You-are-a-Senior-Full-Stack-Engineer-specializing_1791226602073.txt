# 3. GAME LOGIC (server is the source of truth)
- **Route generation:** on first "Begin Voyage", create a per-team shuffled route (Fisher-Yates with `crypto.randomInt`) inside one DB transaction. Idempotent: starting twice never reshuffles. Best-effort: no two teams share the same first checkpoint (when teams ≤ checkpoints), and no two teams have identical full orders.
- **Capture validation (server-side Haversine):** compute distance to the team's CURRENT checkpoint only. Capture when `distance <= radiusM` AND `accuracy <= max(radiusM, 30)`. Require 2 consecutive qualifying pings, or 1 ping plus a client "arrive" event the server re-validates. Configurable via env/constants.
- **Campus GPS reality:** NITK has tree cover and buildings, so default `radiusM` is 30 m (admin-adjustable), and the accuracy gate is relaxed to `max(radiusM, 40)` by default. Make both tunable in the admin UI under "Game Settings".
- On capture: write `Completion`, increment `currentIndex`, emit `checkpoint:captured` to the team (with the NEXT checkpoint's coordinates) and `admin:team:update` + `admin:completion:new` to admins. Last checkpoint sets FINISHED and emits `voyage:complete`.
- **Never send future checkpoint coordinates to a team client**, only the current one.
- **Anti-cheat:** flag (don't silently drop) pings implying > 12 m/s between fixes; flag accuracy exactly 0 or identical repeating coordinates; flags appear on the admin dashboard.
- **Admin edits mid-game:** checkpoints are soft-deleted via `isActive`; if a team's current checkpoint is deactivated, auto-advance and notify them.
- **Event controls:** admin can Start / Pause / End the whole event. While paused or not started, teams see a themed waiting screen ("The Gods Are Still Sleeping") and captures are rejected.

# 4. REST + SOCKET CONTRACT
**REST:** `POST /api/auth/team/login`, `POST /api/auth/admin/login`, `POST /api/auth/logout`, `GET /api/auth/me`; `POST /api/game/start`, `GET /api/game/state`; admin CRUD for `/api/admin/checkpoints` and `/api/admin/teams`, `POST /api/admin/teams/:id/reset`, `GET /api/admin/overview`, `GET/PATCH /api/admin/settings`, `POST /api/admin/event/{start|pause|end}`, `GET /api/admin/export.csv`.
**Socket:** JWT auth in handshake; teams join `team:{id}`, admins join `admins`.
- Client → Server: `location:update {lat,lng,accuracy,heading?,ts}`
- Server → Team: `checkpoint:captured`, `target:update`, `voyage:complete`, `event:status`, `error:flagged`
- Server → Admins: `admin:snapshot` (on connect), `admin:team:update`, `admin:completion:new`
- Reconnect: client re-syncs from `/api/game/state`; server never double-awards a capture. Max 1 location event per 3 s per socket.

# 5. TEAM VIEW (mobile-first)
**5.1 Splash/Login:** ODECEEE + "The Odyssey" branding, team name + passcode, and a big glowing **"Begin Voyage"** button. On tap, in this order: (a) create/resume `AudioContext` and play a silent buffer (mobile audio unlock), (b) request geolocation permission, (c) `DeviceOrientationEvent.requestPermission()` on iOS, (d) request Screen Wake Lock, (e) `POST /api/game/start`. Every denial gets a themed, actionable screen with per-browser instructions (iOS Safari and Android Chrome).

**5.2 The 39-Second Oracle (no map, ever):**
- Continuous `navigator.geolocation.watchPosition` (`enableHighAccuracy: true`, `maximumAge: 0`, `timeout: 20000`) writes to a ref, not React state.
- One 39,000 ms cycle. At each tick, snapshot the latest position, compute bearing + distance, animate the compass needle. The UI is deliberately frozen between ticks.
- Glowing circular 39-second countdown ring (SVG), driven by `performance.now()` (not an incrementing `setInterval`) so it survives tab throttling.
- Compass uses `deviceorientationabsolute` / `webkitCompassHeading` to point relative to device heading. Fallback with no sensor: a text readout ("The Oracle whispers: North-East") plus a distance band (Far / Near / Close / Very close) instead of exact meters.
- GPS status in themed text: "The heavens are clear" / "Hades' Veil descends".

**5.3 The Siren's Song (Web Audio API, procedural, no audio files needed):**
- 2 detuned sine/triangle oscillators + a low-gain filtered noise layer → BiquadFilter (lowpass) → GainNode, with a gentle LFO for shimmer. Optionally prefer a looping file from `/client/public/audio` if present.
- Computed on the frontend via Haversine on EVERY GPS update (independent of the 39 s UI refresh):
  - `> 100 m`: silent (gain ramped to 0)
  - `100 m → radius`: gain 0.05 → 1.0, oscillator 220 → 880 Hz, filter cutoff and LFO rate rising with an ease-in curve
- All parameter changes via `setTargetAtTime` / `linearRampToValueAtTime` (no clicks). Master volume slider and mute button. Auto-resume on `visibilitychange` / suspended context with a "Tap to hear the Sirens" prompt. Celebratory chime on capture.
- Visual audio-intensity indicator (glowing waveform bars) for accessibility and for noisy campus areas.

**5.4 Arrival:** full-screen "You Have Reached the Destination" (gold burst, laurel-wreath animation, `navigator.vibrate`), shows checkpoint name + optional hint/lore, then "Continue the Voyage" loads the next target and restarts the 39 s cycle. Finale: "The Odyssey Is Complete" with total time and the list of checkpoints with timestamps.

**5.5 Location → server:** emit `location:update` every 7 s while visible (latest-value snapshot). If movement < 5 m for 30 s, pause emits but send a heartbeat every 20 s.

**5.6 Resilience:** offline banner, auto-reconnect, queued last position, state restored after refresh/crash from the server, handles "permission revoked mid-game", works acceptably on slow campus Wi-Fi/mobile data (small payloads).
